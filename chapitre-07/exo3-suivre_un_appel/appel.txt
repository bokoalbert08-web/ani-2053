Les sauts : appel suivi : target.Clear(couleur), écrit dans OnRender d'une NkCanvasApp.
1. include/NKCanvas/App/NkCanvasApp.h, ligne 262, virtual void OnRender(NkRenderWindow &target) : c'est la fonction que l'application redéfinit et dans laquelle elle écrit target.Clear(couleur). Ce qui s'y décide : le type de target est NkRenderWindow.
2. include/NKCanvas/Renderer/Targets/NkRenderWindow.h, ligne 77, void Clear(const NkColor2D &color = NkColor2D::Black) override; : Clear est seulement déclarée dans l'en-tête, avec override et sans corps. La classe hérite de NkRenderTarget (ligne 49) et contient un NkRenderer2D mFacade (ligne 184, « facade user-facing »). Ce qui s'y décide : Clear est une redéfinition d'une fonction de la classe parente.
3. include/NKCanvas/Renderer/Targets/NkRenderTarget.h, ligne 55, virtual void Clear(const NkColor2D &color = NkColor2D::Black) = 0; : la virtuelle pure de la classe parente, sous le commentaire « Vide le framebuffer avec la couleur indiquée ». Ce qui s'y décide : le contrat commun à toutes les cibles de rendu (NkRenderTexture redéfinit aussi Clear, ligne 73 de NkRenderTexture.h).
4. include/NKCanvas/Renderer/Core/NkRenderer2D.h, lignes 101 à 104, void Clear(const NkColor2D &c = NkColor2D::Black) { if (mBackend) mBackend->Clear(c); } : la façade transmet l'appel au moteur de rendu 2D, s'il existe. Ce qui s'y décide : la façade ne dessine pas, elle délègue à mBackend.
5. include/NKCanvas/Renderer/Core/NkIRenderer2D.h, ligne 73, virtual void Clear(const NkColor2D &color = NkColor2D::Black) = 0; : une virtuelle pure. Ce qui s'y décide : c'est l'interface que chaque moteur de rendu doit remplir, et la suite dépend de la classe concrète choisie.

Arrêt : NkIRenderer2D::Clear (NkIRenderer2D.h, ligne 73).

Pourquoi là : j'ai été arrêté par une virtuelle pure (= 0) : la route devient un embranchement, qui dépend du moteur de rendu concret. Les moteurs déclarent chacun leur Clear en override : NkOpenGLRenderer2D.h ligne 30, NkDX11Renderer2D.h ligne 41, NkDX12Renderer2D.h ligne 45, NkVulkanRenderer2D.h ligne 40, NkMetalRenderer2D.h ligne 45 et NkSoftwareRenderer2D.h ligne 27, tous sans corps dans l'en-tête. Au-delà, le code est dans les bibliothèques déjà compilées du dossier lib/ : le kit ne contient que des en-têtes et des bibliothèques, donc je ne peux pas aller plus loin. Je me suis arrêté là parce qu'on n'apprend plus rien de plus dans les en-têtes.

Ce que je sais maintenant : ce que j'ai vu dans les en-têtes : target est une NkRenderWindow ; NkRenderWindow::Clear est déclarée en override, sans corps dans l'en-tête ; la parente NkRenderTarget la déclare virtuelle pure ; la façade NkRenderer2D::Clear transmet à mBackend->Clear(c) si mBackend existe (corps visible, lignes 101 à 104) ; NkIRenderer2D::Clear est une virtuelle pure ; six moteurs de rendu la redéfinissent. J'ai aussi vu qu'un moteur peut ne rien faire : dans NkVulkanRenderer2D.h, ligne 170, une version de Clear a un corps vide, dans une classe dont IsValid() rend false. Ce que je suppose sans l'avoir vu : que le corps de NkRenderWindow::Clear appelle mFacade.Clear (son corps n'est pas dans l'en-tête, donc je ne l'ai pas lu) ; quel moteur de rendu est choisi sous Windows (NkCanvasApp.h parle d'un ordre pour macOS et d'une résolution du moteur par ResoudreBackend, mais je n'ai pas vu l'ordre pour Windows) ; et ce que fait réellement Clear dans chaque moteur, par exemple pour OpenGL : son corps est dans la bibliothèque compilée.
